# Plan: Fix Ship Agent "Confirm & Act" Flow

## Context

The ship agent (`.kilo/agents/ship.md`) runs a pre-push quality gate and then uses the `question` tool to offer three options: "Commit and push", "Commit only", or "Cancel". However, the current instructions are ambiguous about what happens *after* the user selects — the git commands are described in parentheses rather than as imperative execution steps. This could cause the agent to report the options without actually running the commands.

Additionally, `git add -u` silently excludes untracked files that the gate already warns about, and cancellation isn't logged.

## Approach

Restructure the "Confirm & Act" section to be explicitly imperative: define a clear post-selection mapping from answer labels → bash tool commands, ensure untracked files are handled explicitly, and add cancellation logging for consistency with other agents.

## Implementation Steps

1. **Rewrite the "Confirm & Act" section in `.kilo/agents/ship.md` (lines 42-50).**
   - Replace the descriptive option list with an imperative flow: "After the user selects, use the `bash` tool to execute the corresponding commands."
   - Define a mapped decision tree: if selected answer contains "Commit and push" → `git add -u && git commit -m "<message>" && git push`; if "Commit only" → `git add -u && git commit -m "<message>"`; if "Cancel" → log event and stop.
   - Add explicit `bash` tool usage instruction so the LLM doesn't just describe the commands.

2. **Add untracked files handling.**
   - If untracked files exist, include a warning in the gate summary that `git add -u` will NOT stage them.
   - If any untracked file appears to be a secret or credential (matching `.env`, `*.pem`, `*.key`, `credentials.*`), elevate the gate to `blocked`.
   - Offer a fourth option only when untracked files exist: "Commit (without untracked files)" to make the exclusion explicit.

3. **Add cancellation event logging.**
   - When the user selects "Cancel", run `node scripts/log-event.mjs user_cancelled ship cancelled "user cancelled at ship gate"` before stopping.
   - This matches the pattern used by code and flash-patch agents.

4. **Verify: run `node tests/validate.mjs` and confirm all 123 tests still pass.**

## Risks / Edge Cases

- **The `question` tool returns an array of label strings.** The agent needs to check `includes("Commit and push")` style matching, not exact equality, since the answer format may vary.
- **PowerShell quoting:** `git commit -m "<message>"` with angle brackets could cause PowerShell issues. Use the single-quote format: `git commit -m 'recommended message here'` with proper escaping.
- **Gate validation must remain unchanged.** The checklist steps (1-4) and "Required Output" section should not be modified — only the "Confirm & Act" section is in scope.
- **Existing 123/123 tests must still pass** after the change.
