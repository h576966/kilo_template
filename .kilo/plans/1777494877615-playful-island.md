# Plan: Fix kilo.jsonc encoding + log-event.mjs warning noise

## Root Cause Analysis

### Issue 1: UTF-16 LE BOM in kilo.jsonc

The file was authored on Windows and saved with UTF-16 LE encoding (likely PowerShell's `Set-Content` default, or Notepad "Unicode" option). Rather than fixing the encoding at the source, a defensive workaround was added: `readText()` in `tests/validate.mjs:14-15` and `scripts/activate-rules.mjs:11-13` detects BOM bytes and decodes accordingly.

The BOM detection was pragmatic but masks the underlying issue. Editors opening the raw file in UTF-8 mode see garbled text. Git diff, grep, and code search tools may not handle it correctly.

### Issue 2: Warning from log-event.mjs CLI guard

`scripts/log-event.mjs:68-69` emits `console.error('Warning: expected 4 args ...')` when invoked with fewer than 4 CLI arguments. The script then exits 0 (line 79: `process.exit(ok ? 0 : 1)`) because `logEvent()` with empty strings doesn't throw.

The warning fires in two scenarios:
- **Direct CLI with < 4 args** (e.g., testing `node scripts/log-event.mjs`): "got 0" → stderr warning → exit 0. Noise.
- **Imported by validate.mjs**: The CLI guard correctly evaluates to `false` — no warning. This path is clean.

The guard itself has a subtlety: the `import.meta.url` comparison fails on Windows (triple-slash `file:///C:/` vs double-slash `file://C:/`), so it relies entirely on `process.argv[1]?.includes('log-event.mjs')`. This works but is fragile — if Node.js ever changes `process.argv[1]` format, the guard could break.

## Approach

**Fix both issues at the source, not with workarounds:**

1. Re-encode `kilo.jsonc` to UTF-8 without BOM. Keep the BOM detection in `readText()` as a defensive safety net — removing it would be a regression for users who accidentally re-introduce BOM files.
2. Clean up the `log-event.mjs` CLI guard: remove the noise warning, simplify the entry-point check. A utility script called with no args should be a silent no-op.

**Why not remove BOM detection from `readText()`:** The function handles `bom16LE`, `bom16BE`, and `bom8`. Removing support would break the template for users who later create files with BOM in Windows editors. The right fix is to fix the file, not remove the safety net.

**Why not make the warning conditional on `args.length > 0`:** If an agent calls the script with 1-3 args, that's still a partial invocation. A silent log with empty fields is better than a stderr warning that makes terminal output look broken. The review-logs script will show incomplete entries if they occur, which is a better diagnostic.

## Implementation Steps

### Step 1: Re-encode kilo.jsonc to UTF-8 without BOM (`model: Flash`)

- Read `kilo.jsonc` content (currently UTF-16 LE with BOM)
- Write back as UTF-8 without BOM using Node.js `fs.writeFileSync(path, content, 'utf-8')`
- Verify: `node tests/validate.mjs` passes (the BOM detection in `readText` handles both encodings, and UTF-8 without BOM is the `toString('utf-8')` path at line 22)

### Step 2: Fix log-event.mjs CLI guard and warning (`model: Flash`)

- Remove the stderr warning on line 68-69 entirely
- Clean up the CLI entry guard on line 66:
  - Replace the fragile dual-condition with a single reliable check: `process.argv[1]?.endsWith('log-event.mjs')` (more precise than `includes`)
  - Remove the `import.meta.url` comparison which is broken on Windows
- When < 4 args: still call `logEvent()` (harmless — writes line with empty fields if no exception, which it won't throw), then exit silently
- Alternative: if < 4 args, skip `logEvent()` entirely, exit 0 — but this changes behavior from "write incomplete log" to "write nothing". Keeping the call is safer (no behavior change for the import path).
- Verify: `node scripts/log-event.mjs` → exits 0, no stderr output
- Verify: `node scripts/log-event.mjs escalation_prompted code fail "test"` → appends JSON line, no stderr
- Verify: `node tests/validate.mjs` → 123 passed, 0 failed, no warning noise

## Risks / Edge Cases

- **Re-encoding doesn't change content**: The file is UTF-16 LE, not UTF-16 BE or mixed. Converting to UTF-8 is lossless — all characters in kilo.jsonc are ASCII-compatible (plain JSON with English comments).
- **BOM detection stays intact**: `readText()` lines 14-15 still handle `bom16LE`. If someone accidentally saves kilo.jsonc as UTF-16 LE again, `readJsonc()` still works. The fix is preventive, not a removal of defense.
- **Import path unchanged**: `validate.mjs` imports `logEvent` from `../scripts/log-event.mjs` — the export is unchanged, the import path is unchanged. No regressions.
- **Agent prompt instructions unchanged**: Agents still call `node scripts/log-event.mjs escalation_prompted ...` with 4 args. The only difference is they no longer see a warning if they accidentally call with wrong args — instead, a silent log entry with empty fields is written, which `review-logs.mjs` can surface.
