# Plan: Industry Best-Practice Takeaways for KiloTemplate

## Research Summary

Analyzed three documentation sources:
- **Kilo Code** (`kilo.ai/docs`) — chat interface, modes, custom rules, sessions
- **GitHub Copilot** (`docs.github.com/en/copilot`) — plan mode, model routing, custom instructions, `/delegate`, `/fleet`, session management
- **Claude Code** (`code.claude.com/docs/en`) — CLAUDE.md, path-scoped rules, auto memory, hooks, skills, subagents, failure patterns, permission modes

**Filter criteria:** Only zero-infrastructure changes (doc/config improvements only).

---

## Takeaway 1: AGENTS.md Self-Improvement Guidance

**Source:** Claude Code — "Treat CLAUDE.md like code: review it when things go wrong, prune it regularly, and test changes by observing whether Claude's behavior actually shifts."

**Problem:** AGENTS.md has no guidance about maintaining itself. Agents don't know when/how to update it.

**Proposed change:** Add a brief "Maintaining These Instructions" section to AGENTS.md:
- Add to AGENTS.md when: agent makes the same mistake twice, code review catches something agent should have known, you typed the same correction last session
- Remove from AGENTS.md when: agent already does it correctly without being told, it's self-evident (e.g., "write clean code")
- Keep AGENTS.md under 200 lines; prune ruthlessly

**Complexity:** Minimal — ~5 lines added to AGENTS.md.

## Takeaway 2: Failure Pattern Documentation

**Source:** Claude Code — "Avoid common failure patterns" (kitchen sink session, over-correcting, over-specified instructions, trust-then-verify gap, infinite exploration)

**Problem:** `10-workflow.md` covers the happy path and escalation policy but doesn't warn agents about common failure modes they themselves cause.

**Proposed change:** Add an "Anti-Patterns" section to `10-workflow.md`:

| Anti-Pattern | Symptom | Solution |
|---|---|---|
| Kitchen sink session | Context polluted with unrelated tasks | Start new session or `/clear` between unrelated tasks |
| Over-correcting | Agent fails, retries same approach 2+ times | After 2 failures, re-plan or escalate (already in policy) |
| Over-specified instructions | Agent ignores instructions because file is too long | Prune rules files; be specific not verbose |
| Trust-then-verify gap | Agent produces plausible but wrong output | Always include verification steps (tests, lint, typecheck) |
| Infinite exploration | Agent reads hundreds of files, fills context | Scope investigations; use worker delegation for focused tasks |

**Complexity:** ~15 lines.

## Takeaway 3: "Skip Plan for Trivial Tasks" Exception

**Source:** Claude Code — "If you could describe the diff in one sentence, skip the plan." Also: Copilot CLI's when-to-plan table.

**Problem:** AGENTS.md and workflow rules currently say "Never code first" with no exceptions. This is too rigid for single-file fixes, typo corrections, or well-scoped micro-changes.

**Proposed change:** Add a "When plan mode adds overhead" note to `AGENTS.md`:

```
## When to Skip the Plan

Skip the plan phase for:
- Trivial fixes: typos, formatting, single-line corrections
- Well-scoped changes: "rename this variable", "add a log line"
- Changes where the diff can be described in one sentence

Always plan for: multi-file changes, new features, refactoring, design decisions.
```

**Complexity:** ~8 lines.

## Takeaway 4: Path-Scoped Rules

**Source:** Claude Code — `.claude/rules/` with `paths` frontmatter to scope instructions to specific file types/directories.

**Problem:** KiloTemplate's `.kilo/rules/` files apply globally. Rule files for specific languages/frameworks would overwhelm context when not relevant.

**Proposed change:** Add a note in `AGENTS.md` (not a code change) that rule files support optional YAML frontmatter with `paths` for scoping:

```markdown
---
paths: ["src/**/*.ts", "*.tsx"]
---
```

This is documentation only — the Kilo platform would need to implement loading logic if it doesn't already support this. Worth mentioning as a convention even if not yet enforced by the runtime.

**Complexity:** ~5 lines added to AGENTS.md skills/rules section. No code changes needed (the runtime already reads these files; scoping is a future enhancement).

## Takeaway 5: Model Selection Rationale

**Source:** Copilot CLI — model table with "Best For" and "Tradeoffs", including Auto model selection. Claude Code — explicit model assignment to agent types.

**Problem:** AGENTS.md has a model column in the agents table but no rationale for the choices.

**Proposed change:** Expand the model column to include "Why":

| Agent | Mode | Model | Why |
|-------|------|-------|-----|
| plan | primary | deepseek-v4-pro | Deep reasoning for system design and architecture |
| ask | primary | deepseek-v4-flash | Fast, cost-effective for read-only questions |
| reviewer | subagent | deepseek-v4-flash | Fast feedback; complex reviews escalate to plan |
| worker | subagent | deepseek-v4-flash | Fast implementation of well-defined steps |

**Complexity:** ~4 additional cells in the existing table.

## Takeaway 6: Verification-Loop Emphasis

**Source:** Claude Code — "Give Claude a way to verify its work. This is the single highest-leverage thing you can do." Both Copilot and Claude Code emphasize test-first verification.

**Problem:** `10-workflow.md` mentions "Lint + Tests Pass" as a gate but never instructs the agent to pre-verify before claiming work is done.

**Proposed change:** Add a note to `10-workflow.md` Phase 2:

```
Before reporting completion, the worker MUST:
1. Run lint and fix any issues
2. Run the test suite and fix any failures
3. Confirm no regressions in related functionality
```

And to `AGENTS.md`:

```
Always provide verification criteria when assigning tasks. The single highest-leverage thing you can do is give the agent a way to check its own work (tests, lint, expected outputs).
```

**Complexity:** ~8 lines.
