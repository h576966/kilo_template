# Plan: Add minimal agent event logging for template tuning

## Context

The user is a solo developer using an AI-assisted workflow (Plan → Execute → Review → Ship). They want a privacy-safe, low-maintenance logging system to capture structured events (escalations, blocked ships, failed validations) so they can spot patterns and improve agent prompts/rules over time. The existing quality-gate model — validate, escalate-after-2, ship readiness — provides clear integration points.

No external dependencies. All scripts use Node.js built-ins. Logs are metadata-only (no code, no secrets, no user data).

## Approach

Three components: a general-purpose CLI logger (`scripts/log-event.mjs`), a weekly review tool (`scripts/review-logs.mjs`), and minimal prompt additions to the 4 agents that produce traceable events.

**Why JSONL + hash fingerprinting**: JSONL is trivially appendable from bash (no parsing needed). A short hash of `event_type:agent:reason` enables dedup analysis in the review script without storing actual error text in the fingerprint.

**Why the logger is a script called via bash**: Agents cannot reliably call internal functions — they already use bash for verification commands. This keeps the pattern consistent and the logger stateless.

**Why validate.mjs imports the logger directly**: validate.mjs runs in Node.js and can import a sibling script — avoids a child_process roundtrip.

### Events captured

| Event | Trigger | Agent | Deterministic? |
|-------|---------|-------|---------------|
| `escalation_prompted` | Agent uses `question` tool for Handoff | code, flash-patch, flash-debug | Best-effort (prompt instruction) |
| `user_cancelled` | User selects "Cancel" in Handoff | code, flash-patch, flash-debug | Best-effort |
| `ship_blocked` | Ship agent reports `blocked` | ship | Best-effort |
| `validation_failed` | `node tests/validate.mjs` exits with failures | — | Deterministic (in-script) |

### What is NOT logged
- `tool_error` — too noisy, poorly defined boundary, not actionable at aggregate level
- User messages, code snippets, file contents, secrets, PII — privacy guardrail enforced by design (only structured metadata fields)
- Successful operations — noise reduction; only deviations are logged

## Implementation Steps

### Step 1: Create `scripts/log-event.mjs` (`model: Pro`)

- Accepts CLI args: `node scripts/log-event.mjs <event_type> <agent> <result> <short_reason>`
- On invocation: creates `logs/` directory if missing, checks `logs/agent-events.jsonl` size
- If size > 5MB: renames to `logs/agent-events-YYYY-MM-DD.jsonl`, keeps max 3 rotated files
- Appends a JSON line: `{"timestamp":"<ISO>","agent":"<arg>","event_type":"<arg>","command":"<optional from env or arg>","result":"<arg>","short_reason":"<arg>","hash":"<sha256[:8] of event_type:agent:short_reason>"}`
- Exits 0 on success, non-zero with message on failure (but never throws — swallows errors so agents aren't blocked)
- Also exports a `logEvent({ event_type, agent, result, short_reason, command? })` function for programmatic use by validate.mjs
- No sensitive data: accepts only the fields listed above, truncates `short_reason` to 200 chars max
- Expected: `node scripts/log-event.mjs escalation_prompted code fail "2 failed lint attempts"` appends one JSON line; `node scripts/review-logs.mjs` shows it

### Step 2: Create `scripts/review-logs.mjs` (`model: Pro`)

- Reads all `logs/agent-events*.jsonl` files
- Outputs a structured summary:
  1. **Event counts by type** (table: event_type, count, last seen)
  2. **Top recurring fingerprints** (hash, count, representative reason, agents affected)
  3. **Recent events** (last 20, chronological)
  4. **Agent-level breakdown** (per agent: total events, escalation rate, cancellation rate)
- All output to stdout — pipeable, reviewable in terminal
- Expected: Run weekly, spot "escalation_prompted surged after adding X rule" or "ship_blocked always on missing test"

### Step 3: Add log calls to agent Handoff sections (`model: Flash`)

- **code.md** Handoff: Before the options list, add: `Before showing the options, log the event: run \`node scripts/log-event.mjs escalation_prompted code fail "<brief reason>"\` via bash.`
- **flash-patch.md** Handoff: Same pattern with agent=`flash-patch`
- **flash-debug.md** Handoff: Same pattern with agent=`flash-debug`
- Also add for the Cancel path: `If the user picks Cancel, also log: run \`node scripts/log-event.mjs user_cancelled <agent> cancelled "user cancelled after <N> failed attempts"\` via bash.`
- Expected: Agents invoked with correct Handoff behavior will produce log lines. 1-2 lines added per agent file.

### Step 4: Add log call to ship.md Confirm & Act section (`model: Flash`)

- In the blocked branch ("When the result is `blocked`, report the issues instead"), add: `Also log: run \`node scripts/log-event.mjs ship_blocked ship blocked "<reason>"\` via bash.`
- Expected: Every blocked ship gate produces a log entry.

### Step 5: Integrate logger into validate.mjs (`model: Pro`)

- Add `import { logEvent } from '../scripts/log-event.mjs';` (relative from `tests/`)
- After the failure path at line 598 (`if (checksFailed > 0) { process.exit(1); }` → before `process.exit(1)`, call: `logEvent({ event_type: 'validation_failed', agent: 'validate', result: 'fail', short_reason: `${checksFailed} checks failed` });`
- Handle the case where the import or log call fails (wrap in try/catch, never crash the validator)
- Expected: `node tests/validate.mjs` with forced failure logs the event and still exits 1

### Step 6: Add `logs/` to `.gitignore` and directory tree (`model: Flash`)

- Add `logs/` line after `# Logs` section in `.gitignore`
- Remove the generic `*.log` line if desired (replaced by directory-level ignore)
- Create `logs/.gitkeep` so the directory exists in the repo template but contents are ignored
- Update `README.md` directory tree to include `logs/`
- Expected: `logs/` appears in directory tree, `git status` ignores log files

### Step 7: Verify (`model: Flash`)

- Run `node scripts/log-event.mjs escalation_prompted code fail "test event"` → confirm JSON line appended
- Run `node scripts/review-logs.mjs` → confirm summary includes the test event
- Run `node tests/validate.mjs` → confirm 123 passed, 0 failed, no log entry written (only logs on failure)
- Delete the test log line manually to keep the log clean
- Expected: Scripts work, agent files pass `checkAgentPromptQuality()`, README directory tree passes

## Risks / Edge Cases

- **Agent doesn't log (best-effort)**: The instruction is a prompt, not a hard gate. If the agent forgets to call the log script, the event is missed. This is acceptable for 80/20 coverage. The review script will show gaps as "zero events for X period" which is itself a signal.
- **Log file grows unchecked**: 5MB rotation limit handles this. At ~200 bytes per event, that's ~25,000 events before rotation — years of solo usage. Rotation keeps the last 3 files (~75,000 events max).
- **Script crashes block agent**: The log script wraps everything in try/catch and never throws. If it can't write, it exits gracefully. Agents continue regardless.
- **Sensitive data leakage**: The script only accepts structured metadata fields. `short_reason` is truncated to 200 chars. No file contents, code, or user input is accepted. The prompt instructions explicitly say "brief reason" — the agent writes a short summary, not a code dump.
- **validate.mjs import circularity**: `tests/validate.mjs` importing from `scripts/log-event.mjs` is a clean DAG (no circular references). Both are ESM `.mjs` files.
- **Conciseness budget**: Each agent Handoff section gains 1-2 lines. Code is at 50 lines, flash-patch at 33, flash-debug at 33, ship at 39 — all well under the 100-line warning threshold.
