# Plan: Add interactive handoff questions to code and ship agents

## Context

Currently, when the code agent hits the 2-failure escalation threshold, it just reports and stops — leaving the user to manually type a follow-up. Similarly, ship produces a flat report with "ready/blocked" but doesn't ask the user what to do next. The user wants explicit question prompts so agents handle the full lifecycle: code asks the model-escalation question, ship asks the commit/push question.

Both the `question` tool (structured multi-choice) and text prompts are available. The `question` tool is ideal here since both scenarios have discrete, well-defined choices.

## Approach

Add a "Handoff" section to `code.md` that replaces the current passive escalation lines with an explicit `question`-tool invocation offering three choices. Add a "Confirm & Act" or similar section to `ship.md` after the gate report that uses the `question` tool to offer commit+push / commit-only / cancel.

No changes to `validate.mjs`, `AGENTS.md`, `README.md`, `kilo.jsonc`, or rules — these are body-only prompt edits in two agent files.

## Implementation Steps

### Step 1: Add interactive escalation to code.md (`model: Pro`)

- Replace the current Escalation section (lines 34-39) with a "Handoff" section.
- After 2 failed attempts, the agent stops trying the same approach and asks the user via the `question` tool:
  - **Continue with V4 Pro** — escalates to `deepseek/deepseek-v4-pro` for another attempt
  - **Continue with V4 Pro + message** — same but with a custom instruction from the user
  - **Cancel** — stops working on the task, reports what was tried
- The section should also cover handoff when a plan step seems wrong/incomplete (flag + ask).
- Keep the "Do NOT auto-escalate" rule — the question IS the handoff, not the escalation.
- Expected: `checkAgentPromptQuality()` still passes verification criteria (the Verification Gate section is unchanged). Identity and rules sections unchanged.

### Step 2: Add commit/push question to ship.md (`model: Pro`)

- Add a "Confirm & Act" section after the Required Output block.
- After the gate review produces a positive result (diff clean, checks pass, message ready), ask via the `question` tool:
  - **Commit and push** (recommended / most common) — runs `git add`, `git commit`, `git push`
  - **Commit only** — runs `git add` and `git commit` without pushing
  - **Cancel** — stops without any git action
- When the gate review finds issues (blocked), still report the issues instead of offering commit options.
- Keep the Required Output section as-is for the gate report itself — just add the question after it.
- Expected: `checkAgentPromptQuality()` still passes (verification language preserved in Required Output). Anti-hallucination language preserved in Rules.

### Step 3: Verify (`model: Flash`)

- Run `node tests/validate.mjs` — all checks pass, 0 failures.
- Expected: code and ship identity statements still pass, ship verification criteria still pass, no regressions.

## Risks / Edge Cases

- **validate.mjs `checkAgentPromptQuality()`**: ship is in `verificationAgents` — the check looks for `/verif|required output|lint.*test|non-negotiable/i`. The Required Output section is kept, so this passes.
- **Conciseness check**: Adding sections might push code.md or ship.md over 100 lines. Ship is at 29 lines (well under), code is at 47 (room for ~50 more). The check only warns, doesn't fail.
- **`question` tool availability**: Both code (primary) and ship (subagent) have access to the `question` tool. Verified in tool listing.
- **Ship blocked scenario**: The plan explicitly handles this — when blocked, ship reports issues and does NOT offer commit options. This prevents accidental commits of bad changes.
